# Stage 01 — Project Foundation & Infrastructure

## Goal

Establish the mono-repo scaffold, Docker Compose orchestration for all five services (postgres, redis, backend, frontend, nginx), a CI pipeline skeleton on GitHub Actions, shared linting configuration, environment variable contracts, and root-level tooling. Every subsequent stage starts from this known, reproducible baseline. No feature logic is written in this stage — only the plumbing that lets all later stages boot cleanly from a single command.

---

## User Stories

1. As a developer, I want a single `docker compose up` command to start all services, so that I can begin developing without manual installation steps.
2. As a developer, I want environment variables documented in `.env.example`, so that onboarding a new contributor takes minutes, not hours.
3. As a CI maintainer, I want linting and formatting checks to run on every pull request, so that code style is enforced automatically.
4. As a security-conscious developer, I want `.gitignore` to cover all secret and build artefact patterns for Python, PHP, Node, and Docker, so that credentials are never accidentally committed.
5. As a developer, I want both services to expose a `/health` endpoint, so that Docker and load balancers can confirm a service is alive.

---

## Acceptance Criteria

1. Running `docker compose up --build` from the repository root brings up five healthy containers: `postgres`, `redis`, `backend`, `frontend`, `nginx`.
2. `docker compose ps` shows all five containers with status `healthy` after initial boot (health checks configured on each service).
3. The `postgres` container exposes port `5432` on the host; `backend` exposes `8000`; `frontend` exposes `9000`; `nginx` exposes `80`.
4. A `.env.example` file at the root documents every required variable with an inline comment; no real secrets appear in any committed file.
5. The root `.gitignore` suppresses: `*.env`, `.env`, `__pycache__/`, `*.pyc`, `vendor/`, `node_modules/`, `.venv/`, `storage/logs/`, `storage/framework/cache/`, `*.sqlite`, `*.pem`, `*.key`, `dist/`, `.DS_Store`.
6. GitHub Actions workflow `.github/workflows/ci.yml` defines at minimum three jobs: `lint-backend`, `lint-frontend`, `build-images`; triggers on `push` and `pull_request` to `main` and `develop`.
7. `lint-backend` runs `ruff check` and `ruff format --check` against `backend/` with zero errors on the stub codebase.
8. `lint-frontend` runs `./vendor/bin/pint --test` against `frontend/` with zero errors on the stub codebase.
9. A `Makefile` at the root provides targets: `up`, `down`, `build`, `migrate`, `test-backend`, `test-frontend`, `lint`.
10. `GET /health` on the backend (port 8000) returns `200 OK` with `{"status": "ok", "service": "backend"}`.
11. `GET /health` on the frontend (port 9000) returns `200 OK` with `{"status": "ok", "service": "frontend"}`.
12. Nginx reverse-proxies `/api/` to `http://backend:8000` and all other paths to `http://frontend:9000`.
13. PostgreSQL initialisation SQL (`postgres/init.sql`) creates two schemas: `calendar_app` and `laravel`, both owned by the `app` user.
14. Redis is reachable from both `backend` and `frontend` containers (verified by a startup ping in each service's entrypoint script).
15. `docker compose down -v && docker compose up --build` (full teardown and rebuild) completes without errors.

## Environment Variables Contract (`.env.example`)

```dotenv
# --- Postgres ---
POSTGRES_HOST=postgres
POSTGRES_PORT=5432
POSTGRES_DB=shared_calendar
POSTGRES_USER=app
POSTGRES_PASSWORD=changeme

# --- Redis ---
REDIS_URL=redis://redis:6379/0

# --- FastAPI backend ---
SECRET_KEY=change-me-at-least-32-chars
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=60
REFRESH_TOKEN_EXPIRE_DAYS=30
BACKEND_CORS_ORIGINS=http://localhost,http://nginx

# --- Laravel frontend ---
APP_KEY=                              # generated by: php artisan key:generate
APP_URL=http://localhost
BACKEND_API_BASE_URL=http://backend:8000
BACKEND_API_TIMEOUT=10
SESSION_DRIVER=redis
CACHE_DRIVER=redis
QUEUE_CONNECTION=redis
REDIS_HOST=redis
REDIS_PORT=6379

# --- Email (used in Stage 05) ---
MAIL_MAILER=smtp
MAIL_HOST=mailpit
MAIL_PORT=1025
```

|------------|----------------------|-------------|---------------------------|
| `postgres` | `postgres:16-alpine` | 5432        | `pg_isready`              |
| `redis`    | `redis:7-alpine`     | 6379        | `redis-cli ping`          |
| `backend`  | `./backend`          | 8000        | `curl /health`            |
| `frontend` | `./frontend`         | 9000        | `curl /health`            |
| `nginx`    | `./nginx`            | 80          | `curl localhost/health`   |
